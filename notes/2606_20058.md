# Autonomous Event-Driven Multi-Agent Orchestration for Enterprise AI at Scale

- **ID:** arXiv:2606.20058 (v1) — verified from https://arxiv.org/html/2606.20058v1 (full text). "Preprint. Under review."
- **Authors:** Harsh Rao Dhanyamraju, Leonidas Raghav, Aaron Lee (SAP SE)
- **Status:** INCLUDE — category: benchmark+system (enterprise orchestration incl. financial close)

## Summary
SAP compares two orchestration architectures (DAG Plan & Execute vs ReAct) plus a Task Manager (priority inference, related-event merging, preemption) for continuous event-driven multi-agent operation. Benchmark: 208 production-derived enterprise scenarios over a mock registry of 200 enterprise agents in 7 departments — Finance is one, with a full financial-close agent fleet (accruals, journal-entry, intercompany, reconciliation, GL review, GR/IR clearing, consolidation), AR/AP (invoice-capture/validation, vendor-reconciliation, smart-clearing), billing/O2C, and FP&A (budgeting-forecasting, scenario-planning). Central finding: registry scale, not task complexity, dominates orchestration performance.

## Tasks
- "The evaluation dataset comprises 208 scenarios derived from actual user stories, enterprise workflows, and business processes, generating 393 events and 1,051 total agent calls." (Sec 3)
- Scales: 95 Persona-level, 63 Department-level, 50 Enterprise-level scenarios; "200 enterprise functions organized into 7 departments (Finance, HR, Procurement, Revenue, Supply Chain, IT, and Customer Support) with 19 specialized personas" (Sec 3).
- Scenario types: Simple / Parallel / Complex / Failure + Priority and Related-Events (Task Manager).
- Example close scenario (App. B): "Title: Revenue Recognition Policy Change Mid-Close ... evt-001: start the May 2026 close by posting accruals, generating analytical insights, and preparing consolidation; expected agents are accruals, analytical-insights, and consolidation; pattern is sequential."

## Eval method
Execution-based orchestration scoring + LLM-judge: "automated scoring of agent discovery precision/recall, execution pattern correctness, entity extraction accuracy, and response completeness" (Sec 3); mock agents classify requests MATCH/CLOSE_MATCH/MISMATCH via entity-identification; "Correctness is measured using LLM-as-judge evaluation, comparing the orchestrator's final synthesized response against the scenario's expected answer fragments" (Sec 4.1).

## Data realism
Synthetic/templated grounded in real material: scenarios generated by LLM from "anonymized user stories from an enterprise agent fleet under active company development, documented workflows, and business process specifications" with two human review gates (Sec 3.2); specialist agents are LLM-powered MOCKS with ground-truth guidelines (Sec 4.1). Raw internal source material and code not released.

## Agent scope
Multi-agent + long-horizon/continuous: A2A protocol orchestration of up to 200 registered agents, event streams, priority preemption, task merging; two orchestration architectures + kernel-style Task Manager.

## Key numbers (quoted)
- Abstract: "The Task Manager reduces high-priority queue latency by 14–75% and improves related-event correctness by over 20 percentage points at enterprise scale."
- Abstract: "scale, not task complexity, dominates orchestration performance".
- Sec 5.1: "Both architectures perform well at Persona level (74–98%) but degrade significantly as agent count increases—Department scores drop to 65–80%, and Enterprise scores fall to 32–83%."
- Sec 5.1: "Simple scenarios degrade from 90–96% (Persona) to 36–54% (Enterprise), while Complex scenarios maintain 73–83%."
- Sec 5.1: "DAG's failure handling collapses at scale (93.7% → 68.3% → 32.4%)".
