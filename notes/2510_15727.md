# Invoice Information Extraction: Methods and Performance Evaluation

- **ID:** arXiv:2510.15727 (v1; LaTeXML generated Oct 2025) — verified from https://arxiv.org/html/2510.15727v1 (full text). NOTE: pre-saved /tmp/paper.txt was unreachable (workspace shell outage), so the paper was refetched from the same arXiv HTML source.
- **Authors:** Sai Yashwant, Anurag Dubey, Praneeth Paikray (ManpowerGroup Services India Pvt. Ltd.), Gantala Thulsiram (IIT Hyderabad)
- **Status:** INCLUDE — category: system (comparative method study, P2P invoice extraction)

## Summary
Industry comparative study of two invoice-extraction paradigms on a curated dataset: (1) Docling — layout-analysis/OCR document-understanding pipeline exporting structured JSON; (2) LlamaExtractor — schema-guided LLM structured extraction (LlamaIndex/LlamaExtract-style, JSON-Schema-constrained decoding), with a routing + parsing + language-detection/translation workflow. Proposes a DocILE-aligned evaluation framework (field-level exact/relaxed match, tolerance windows, line-item metrics, business-rule consistency checks). LLM-based extraction wins decisively on accuracy and consistency at higher latency/cost.

## Tasks
- Dataset: "A curated data set of 102 digitally born and scanned invoice documents in PDF and JPEG format" varying in "layout, language (e.g., English, German) and complexity"; manual ground-truth JSON (invoice_number, issue_date, due_date, seller_name, seller_address, total_amount, tax_amount, line_items); synthetic augmentation via image rotation (Sec 3.1).
- 5 schema entities: bill-to, supplier, invoice, line item, tax line summary (Sec 4).
- 2 methods compared; no model-family sweep.

## Eval method
Exact-match style with business-rule checks: "Exact match and relaxed match scoring", "Tolerance windows for numeric fields", F1 for field presence; line-item "row-wise assignment accuracy" and "table-level completeness" (Sec 3.4, aligned to DocILE KILE/LIR); plus consistency checks encoding business rules, e.g., "net amount + tax amount + roundoff amount = gross amount" (Sec 4.1). No LLM-judge, no human eval.

## Data realism
Real (102 curated real digital + scanned invoices, multi-language, multi-vendor) with synthetic rotation augmentation; dataset is proprietary/curated, not released.

## Agent scope
Pipeline, not agent: schema-constrained single-pass LLM extraction inside a routed workflow (complexity-based router, parsing, language detection, translation, then extraction; Sec 3.3). Confidence score + rationale per field to support human-in-the-loop triage. No multi-step agent loop, no tool use by the model.

## Key numbers (quoted)
- Sec 4.3.1: "The LlamaExtractor shows superior accuracy, achieving an overall extraction accuracy of 94%, compared to 63% for the Docling method."
- Sec 4.3.1: "the Docling method exhibits faster average processing times (10 seconds per document) relative to the LlamaExtractor (30 seconds per document)."
- Sec 4.3.2: "The LlamaExtractor achieves a consistency check pass rate 93% ... the Docling method records an 80% pass rate"; "the LlamaExtractor recorded zero mathematical validation errors, while the documentation [Docling] exhibited 20 errors."
- Sec 4.1 (Docling detail): invoice_name/invoice_number accuracy 90%; tax_amount/net_amount/currency_format 60%; line items 58%.
- Sec 4.2: LlamaExtractor line-item entity accuracy 91%.
