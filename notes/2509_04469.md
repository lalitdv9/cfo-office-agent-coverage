# Multi-Modal Vision vs. Text-Based Parsing: Benchmarking LLM Strategies for Invoice Processing

- **ID:** arXiv:2509.04469 (v1; LaTeXML generated Aug 2025) — verified from https://arxiv.org/html/2509.04469v1 (full text)
- **Authors:** David Berghaus, Armin Berger, Lars Hillebrand, Kostadin Cvejoski, Rafet Sifa (Fraunhofer IAIS; Lamarr Institute)
- **Status:** INCLUDE — category: benchmark (P2P invoice document processing)

## Summary
Benchmarks eight multi-modal LLMs (GPT-5 family: gpt-5-chat/mini/nano; Gemini 2.5 pro/flash/flash-lite; open-source Gemma 3 12b/4b) on three open invoice/receipt datasets with zero-shot prompting, comparing two strategies: native image processing vs "structured parsing" (Docling image-to-markdown, then text-only LLM). Native vision consistently wins; the OCR/markdown conversion is the bottleneck. Code released (anonymized repo).

## Tasks
- 3 datasets (Sec III-D): Clean Invoices (Donut) = 500 synthetic invoices; Scanned Receipts (ICDAR-2019-SROIE) = 1,000 real scanned receipts (company, address, date, total); Scanned Invoices (inv-cdip) = 350 real scanned invoices with 7 fields (invoice number, PO, invoice date, due date, amount due, total amount, total tax).
- 8 models x 2 strategies; field-level structured extraction to JSON.

## Eval method
Exact-match: "we considered a field to be correctly extracted if it matched the ground truth exactly after minimal normalization" (dates/whitespace normalized; no comma/dot correction on numbers) (Sec III-E). Metrics: overall accuracy, field-specific accuracy. No LLM-judge, no humans, no execution.

## Data realism
Mixed: 500 SYNTHETIC invoices (Donut) + 1,350 REAL scanned documents (SROIE receipts; inv-cdip tobacco-industry invoices with stamps/handwriting). Authors flag contamination risk: "the datasets are open source, so it is possible that they have been used as training data for the large language models" (Sec III-D).

## Agent scope
None — single-pass zero-shot extraction (QA/extraction). No tool use, no multi-step agent loop.

## Key numbers (quoted)
- Sec IV-A: "on the Scanned Receipts dataset, the top-performing model achieved 87.46% accuracy with native processing, compared to a maximum of only 47.00% using the Docling method. A similar gap was observed for Scanned Invoices, where native processing reached 92.71% versus 64.03% for the parsed text approach."
- Sec IV-B: "Gemini 2.5 Pro consistently achieved the highest accuracy across all three datasets: 87.46% on Scanned Receipts, 96.50% on Clean Invoices, and 92.71% on Scanned Invoices."
- Sec IV-B: "the smaller gemma-3-4b-it model struggled significantly with direct image analysis, especially on the Clean Invoices dataset (45.69%)".
- Sec IV-C: IBAN extraction markedly worse than other fields; "Common mistakes appear to be OCR-related, such as confusing the number zero with the letters 'O' or 'U'."

- **7.1 ●** P2P — invoice/receipt field extraction is the AP invoice-capture step of procure-to-pay; the entire benchmark is this task ("Invoice and order processing represents a ubiquitous and resource-intensive business function", Sec I).
