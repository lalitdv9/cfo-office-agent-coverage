# Organizational Memory for Agentic Business Process Execution

- **ID:** arXiv:2607.03228 (v1, cs.AI, 03 Jul 2026) — verified from https://arxiv.org/html/2607.03228v1 (full text)
- **Authors:** Lukas Kirchdorfer, Adrian Rebmann, Christian Warmuth, Timotheus Kampik, Theiss Heilker, Gregor Berg (SAP Signavio, Berlin, Germany)
- **Status:** INCLUDE — category: system (concept + architecture + proof-of-concept for agentic P2P execution)

## Summary
Introduces "organizational memory" for agentic business process execution: a shared, human-governed, agent-consumable reference layer of organization-specific procedural knowledge (policies, SOPs, BPMN models, ERP documentation, execution experience). Knowledge is decomposed into "process atoms" (name/source/applicability/action/purpose + Enterprise-Domain-Model tags), curated via an LLM "Global Curator" plus human expert review, and served to runtime agents by a Retriever (hybrid tag-filter + semantic/LLM selection). Derives 9 requirements (R1-R9) and demonstrates a proof-of-concept on a purchase-to-pay (P2P) scenario: a procurement-assistant agent that creates or refuses purchase requisitions (PRs) in an ERP system.

## Tasks
- 1 evaluated task: PR creation/refusal compliance in a P2P process — 10 scenarios (compliant requests, single-policy violations, multi-policy joint reasoning), each with binary Create/Refuse ground truth + PR field values (material, quantity, vendor).
- Knowledge corpus: 9 manually created PDF documents (5 procurement + 4 distractors, e.g., HR) encoding 11 distinct P2P rules (approval thresholds, supplier restrictions, category-specific requirements, exception handling).
- Motivating (not evaluated) example: invoice-matching agent deciding auto-post vs route-to-specialist vs compliance review.

## Eval method
Rule-based: Policy Compliance Rate (PCR) = fraction of scenarios with policy-compliant outcome; Create scenarios "correct only if it creates a PR with the expected material, quantity, and vendor, which we verify through rule-based comparison against ground-truth fields"; Refuse scenarios correct only if no PR created. Averaged over 10 scenarios x 4 runs; 3 setups (Base / RAG top-5 ChromaDB chunks with text-embedding-3-large / Memory) x 2 LLMs (GPT-4.1, Claude Sonnet 4.5). No LLM-judge, no human raters.

## Data realism
Synthetic: "we construct a synthetic document collection representing the organizational knowledge base of a hypothetical company"; rules manually specified and embedded in realistic document contexts; ground truth manually created by the authors. Authors caution: "the results should be interpreted with caution, given the preliminary nature and limited scope of the evaluation" (Sec 6.2) and note generalization "to real enterprise settings ... is not yet demonstrated" (Sec 7).

## Agent scope
Single LLM-based runtime agent (procurement assistant) that decides on and executes PR creation, augmented at runtime by retrieved memory atoms; architecture also includes an active Global Curator (quality/duplicate/conflict checks vs existing memory) and human-in-the-loop governance (ownership, approval workflows, access control — R8). Enterprise-level ambition (many agents sharing one memory, R9), but PoC evaluates one agent on one process. Source code proprietary (SAP); eval data/ground truth at github.com/lukaskirchdorfer/org-memory-paper.

## Key numbers (quoted)
- Sec 6.2: "The organizational memory agent achieves the highest PCR for both models, reaching 88% with GPT-4.1 and 95% with the more advanced Sonnet 4.5. It clearly outperforms both the base agent, which reaches 30% for both models, and the RAG-based agent, which reaches 70% with GPT-4.1 and 80% with Sonnet 4.5."
- Sec 6.1: "The collection consists of 9 manually created PDF documents, comprising 5 procurement-related documents and 4 distractor documents from other organizational functions, such as HR." ... "encode 11 distinct rules governing the purchase-to-pay process."
- Sec 6.1: "We designed 10 scenarios, each representing a specific employee request to the agent."
- Sec 6.2 (failure mode): "Its remaining errors are mainly over-restrictions ... caused by an imprecisely extracted atom whose applicability scope is too broad."
- Sec 6.2 (RAG failure mode): "RAG still fails in scenarios where the required rule is cross-cutting rather than query-specific" (e.g., mandatory cost-center rule in a finance policy not retrieved for a notebook request).

## Leaf tags (justified)
- **7.1 ●** P2P — entire PoC is purchase-to-pay: PR-creation agent evaluated end-to-end; motivating example is invoice matching; rules cover approval thresholds/supplier restrictions in P2P.
- **9.1 ◐** ERP/automation — agent operates "in the company's ERP system"; architecture is enterprise agent-automation infrastructure (successor to RPA framing), but no real ERP integration evaluated.
- **9.2 ◐** data-governance — memory curation is explicitly a governed knowledge layer: ownership, read/write permissions, approval workflows, accountability (R8); governance of procedural knowledge feeding agents rather than financial master data.
